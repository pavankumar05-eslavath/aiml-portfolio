# Data

Everything about where the catalogue comes from, which fields are real, and which
are not.

## Source dataset

[`ashraq/fashion-product-images-small`](https://huggingface.co/datasets/ashraq/fashion-product-images-small)
on the Hugging Face Hub — a public mirror of the "Fashion Product Images (Small)"
catalogue.

| | |
|---|---|
| Products | 44,072 |
| Image size | 60 × 80 px JPEG |
| Download | ~260 MB (two Parquet shards) |
| Authentication | none required |

**Why this dataset.** Every product has *both* an image and structured
attributes. Image-only or text-only corpora cannot exercise a multimodal system
at all, and its attribute taxonomy is what makes quantitative evaluation possible
without hand-labelling thousands of query/product pairs (see
[`../docs/evaluation.md`](../docs/evaluation.md)).

**The trade-off.** 60 × 80 source images are small. CLIP upsamples them to
224 × 224, so fine visual detail — stitching, texture, logos — is simply not
present. This bounds achievable visual precision and is listed as a known
limitation in the main README. It is also what makes CPU-only indexing of
thousands of products practical, which is the reason the dataset was chosen.

## Field provenance

The source data does **not** contain a brand column, a description, or a price.
Three fields are therefore derived, and they are not equally trustworthy:

| Field | Status | How it is produced |
|---|---|---|
| `category` (masterCategory) | **Real** | Verbatim from the dataset |
| `subcategory` (articleType) | **Real** | Verbatim from the dataset |
| `colour`, `gender`, `usage`, `season`, `year` | **Real** | Verbatim from the dataset |
| `name` (productDisplayName) | **Real** | Verbatim from the dataset |
| `brand` | **Extracted** | Mined from `name` — see below |
| `description` | **Derived** | Templated from the real attributes above. States no new facts. |
| `price` | **SYNTHETIC** | Deterministically generated. **Not real data.** |

### `brand` — extracted, not invented

In this dataset `productDisplayName` reliably begins with the brand
(`Nike Men's As Spher White T-shirt`, `Casio Youth Series Men Digital Watch`).
The brand is therefore *mined* from the name rather than fabricated, by
[`app/data/enrichment.py`](../backend/app/data/enrichment.py):

1. Count how many distinct products each leading 1–4-word n-gram introduces.
2. Exclude words the dataset itself uses as attribute values (colours, genders,
   article types), so `Men` or `Black` can never be read as a brand.
3. Take the shortest frequent n-gram, then extend it only while the extension is
   a connector (`and`, `of`, `&`) or is nearly as frequent as the base.

That last rule is what distinguishes a genuine multi-word brand from a
descriptive second word:

| Display name | Extracted | Why |
|---|---|---|
| `Gini and Jony Girls Red Skirt` | `Gini and Jony` | every *Gini* product is a *Gini and Jony* product |
| `Turtle Check Men Navy Blue Shirt` | `Turtle` | *Check* follows *Turtle* only occasionally — it describes the pattern |
| `United Colors of Benetton Men Blue Jeans` | `United Colors of Benetton` | connector words bridged |
| `Yves Saint Laurent Men Kouros Perfume` | `Yves Saint Laurent` | too rare for frequency evidence; recovered by the capitalisation fallback |

Measured on 22,036 products: **98.5% brand coverage, 478 distinct brands.**

### `description` — derived, states no new facts

A caption-style sentence composed from the product's own attributes:

> *Puma Men Standpunkt Brown Casual Shoes is a pair of brown casual shoes from
> Puma. It is designed for men and suited to casual wear. Part of the fall season
> 2011 range. Listed under Footwear.*

Every clause restates a value already in the dataset. The purpose is modelling,
not decoration: CLIP's text tower was trained on caption-like alt-text, not retail
SKU strings, and feeding it a caption measurably improves cross-modal retrieval.
Measured on the sample catalogue (48 products probed):

| Text fed to the encoder | image→text top-1 |
|---|---|
| Attribute template | **0.812** |
| Raw catalogue name | 0.771 |

Reproduce with `python scripts/verify_embedding_space.py`.

### `price` — synthetic

**The source dataset has no price column.** Prices are generated by
`synthesise_price()`: a SHA-256 hash of the product id selects a point inside a
hand-set band per article type, adjusted by a usage multiplier, rounded to a
retail-looking ending.

* **Deterministic** — the same product always gets the same price, so re-running
  ingestion does not churn the catalogue and evaluation runs stay comparable.
* **Plausible, not real** — watches cost more than flip-flops, and that is the
  entire extent of the realism.
* **Never load-bearing** — price exists so that price filtering and sorting can be
  demonstrated and tested for *correctness* (does the filter exclude the right
  rows?). No evaluation query depends on price, and the UI labels it as synthetic.

## What is committed to git

| Path | Committed? | Why |
|---|---|---|
| `sample/products.csv` | **Yes** (1,000 rows, 324 KB) | Makes the repo self-describing; lets tests run without network |
| `sample/images/` | **No** (~4 MB) | The upstream dataset declares no licence, so images are not redistributed |
| `full/`, `eval/`, `raw/`, `local/` | **No** | Generated artefacts and downloaded shards |

Fetch the images the committed CSV references:

```bash
python scripts/prepare_sample.py
```

This needs network access, which costs nothing extra in practice — the CLIP
weights are downloaded from Hugging Face on first run anyway.

## Building a larger catalogue

```bash
# 6,000 products, stratified across article types (what the reported evaluation uses)
python scripts/download_dataset.py --limit 6000 --out data/eval
python scripts/index_catalog.py --source data/eval/products.csv

# the whole 44,072-product dataset
python scripts/download_dataset.py --all --out data/full
```

Sampling is **stratified by article type**, not a head-of-file slice: the first
rows of the dataset are dominated by whichever types happen to appear first, which
would leave the demo and the evaluation unrepresentative. Round-robin selection
across types keeps all 141 present. Selection is seeded (`--seed`), so it is
reproducible.

> Rebuilding `sample/products.csv` with a different `--size` or `--seed`
> invalidates the committed evaluation ground truth, which was derived from the
> current file. Regenerate it, or keep the defaults.

## Bringing your own catalogue

The indexer consumes a plain CSV, so no code changes are needed. Required
columns are `external_id` and `name`; everything else is optional:

```
external_id,name,description,category,subcategory,brand,colour,gender,usage,season,year,price,currency,image_url,in_stock
SKU-1,Acme Running Shoe,Lightweight trainer,Footwear,Sports Shoes,Acme,Black,Men,Sports,Summer,2024,79.99,USD,my_images/sku-1.jpg,true
```

`image_url` may be an HTTP(S) URL (fetched during ingestion) or a path relative to
`IMAGE_ROOT`. Rows that fail validation are reported with their line number and
skipped — one malformed row does not discard the file.

```bash
python scripts/index_catalog.py --source path/to/products.csv
```
